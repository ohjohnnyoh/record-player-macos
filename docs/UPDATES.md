# Обновления Record

Record 1.7 использует Sparkle 2.9.4. Приложение проверяет подписанный appcast
раз в сутки. Пользователь может обновиться сразу, отложить предложение на сутки
или пропустить конкретную версию.

## Модель безопасности

- Архивы и appcast подписываются отдельным EdDSA-ключом Sparkle.
- Публичный ключ находится в `Resources/Info.plist`.
- Приватный ключ хранится в macOS Keychain и не попадает в репозиторий.
- Feed и архивы в продакшене загружаются только по HTTPS.
- Бандл приложения подписан ad-hoc. Developer ID и нотарификация для этого
  личного проекта не используются.
- Hardened Runtime не включается: без Developer ID его Library Validation
  отклоняет готовый Sparkle.framework как код другой команды на macOS 26.

Ad-hoc подпись не отменяет Gatekeeper при первой ручной установке. После того
как пользователь уже установил приложение, Sparkle проверяет обновление по
EdDSA и выполняет замену приложения самостоятельно.

## Подготовка релиза

1. Обновить `CFBundleShortVersionString` и `CFBundleVersion` в
   `Resources/Info.plist`.
2. Добавить полные заметки `docs/RELEASE-X.Y.md` и короткий текст для панели
   `docs/APPCAST-X.Y.md`. Если короткого файла нет, скрипт использует полные
   заметки.
3. Выполнить строгую сборку и тесты:

   ```bash
   swift test
   swift build -c release -Xswiftc -warnings-as-errors
   ```

4. Собрать ZIP и appcast:

   ```bash
   ./scripts/build_update_release.sh
   ```

5. Сначала загрузить `Record-X.Y.zip` в GitHub Release `vX.Y`.
6. Только после доступности ZIP заменить корневой `appcast.xml` файлом из
   `build/update-release/appcast.xml` и отправить изменение в ветку `main`.
7. Скачать ZIP с GitHub и сравнить SHA-256 с локальным артефактом.

Такой порядок не оставляет опубликованный feed со ссылкой на ещё не загруженный
архив.

## Сквозной локальный тест

```bash
./scripts/prepare_qa_update.sh
python3 -m http.server 8765 --directory build/update-qa/feed
open "build/update-qa/apps/Record QA 1.6.90.app"
```

В QA-приложении выбрать `Record → Проверить обновления…`, затем проверить:

1. Показана версия 1.6.91 и заметки к релизу.
2. `Напомнить завтра` закрывает панель и не предлагает ту же версию при
   фоновой проверке до истечения суток.
3. Ручная проверка всё равно показывает отложенную версию.
4. `Пропустить эту версию` скрывает 1.6.91 для фоновых проверок.
5. `Обновить` загружает ZIP, показывает прогресс, устанавливает версию 1.6.91
   и перезапускает QA-приложение.
6. После перезапуска `О программе` показывает 1.6.91.

QA использует отдельный bundle identifier и не затрагивает установленный Record.
